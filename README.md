# WAP CLUB Bot — миграция с Google Apps Script на Node.js (Railway)

Всё ниже можно сделать с телефона через обычный браузер — командная строка нигде не обязательна.

## Зачем это нужно

На Apps Script каждый запрос запускал "холодный" контейнер — отсюда были задержки
до нескольких минут. Здесь бот — обычный постоянно запущенный Node.js-процесс:
задержка = реальное время работы кода (десятки-сотни миллисекунд), без холодных стартов.

Google Таблица остаётся базой данных — просто доступ к ней теперь идёт не из GAS,
а через официальный Google Sheets API с отдельным сервисным аккаунтом.

---

## Шаг 1. Создать сервисный аккаунт Google (доступ к таблице)

1. Откройте **console.cloud.google.com** (под тем же Google-аккаунтом, где лежит таблица).
2. Если проекта ещё нет — вверху слева "Select a project" → **New Project** → любое имя, например `wap-club-bot` → Create.
3. В поиске сверху введите **Google Sheets API** → откройте → нажмите **Enable**.
4. В левом меню: **APIs & Services → Credentials** → **Create Credentials → Service account**.
5. Введите любое имя (например `wap-bot-sheets`) → Create and Continue → Done (роль можно не назначать, права дадим прямо на таблице).
6. Откройте созданный сервисный аккаунт → вкладка **Keys** → **Add Key → Create new key** → тип **JSON** → Create.
   Файл скачается автоматически — откройте его любым текстовым просмотрщиком на телефоне.
7. В этом JSON вам нужны два значения:
   - `client_email` — что-то вроде `wap-bot-sheets@wap-club-bot.iam.gserviceaccount.com`
   - `private_key` — длинная строка, начинается с `-----BEGIN PRIVATE KEY-----`

## Шаг 2. Дать сервисному аккаунту доступ к таблице

1. Откройте вашу Google Таблицу с заказами.
2. Кнопка **"Настройки доступа" / "Share"** (обычно вверху справа).
3. Вставьте туда `client_email` из шага 1 (это просто email — таблица добавит его как обычного пользователя).
4. Уровень доступа — **Редактор / Editor**.
5. Сохранить.

Без этого шага бот получит ошибку доступа при первой же попытке записи.

## Шаг 3. Залить код в GitHub

1. Зайдите на **github.com**, войдите или зарегистрируйтесь.
2. **New repository** → назовите, например, `wap-club-bot` → Create repository (Private — ваш выбор, не принципиально).
3. На странице пустого репозитория нажмите **"uploading an existing file"** (или Add file → Upload files).
4. Загрузите ВСЕ файлы из этого проекта, кроме `.env` (его быть не должно — там секреты).
   Файлы: `package.json`, `index.js`, `telegram.js`, `sheets.js`, `texts.js`, `state.js`, `setup.js`, `.gitignore`.
5. Commit changes.

## Шаг 4. Задеплоить на Railway

1. Зайдите на **railway.app**, войдите через GitHub (это упростит следующий шаг).
2. **New Project → Deploy from GitHub repo** → выберите `wap-club-bot`.
3. Railway сам определит Node.js-проект и запустит `npm install` + `npm start`.
4. Пока идёт первый деплой, откройте вкладку **Variables** этого сервиса и добавьте переменные окружения (по одной, кнопка "New Variable"):

   | Имя | Значение |
   |---|---|
   | `BOT_TOKEN` | токен вашего бота от @BotFather |
   | `ADMIN_ID` | `398457938` |
   | `SHEET_ID` | `1bH0mP0ms6eqWVUfDwjkzIx79aV9lxlnrfB5yx22gHlk` |
   | `SHEET_NAME` | `Заказы` |
   | `GOOGLE_CLIENT_EMAIL` | значение `client_email` из шага 1 |
   | `GOOGLE_PRIVATE_KEY` | значение `private_key` из шага 1, вставить как есть, целиком, включая `-----BEGIN...` и `-----END...` |

   Про `GOOGLE_PRIVATE_KEY`: вставляйте ровно то, что было в JSON-файле (со всеми `\n` внутри) —
   код сам разберётся с форматом переносов строк, не нужно ничего вручную менять.

5. **Settings → Networking → Generate Domain** — Railway выдаст публичный HTTPS-адрес вида
   `https://wap-club-bot-production.up.railway.app`. Скопируйте его.

## Шаг 5. Подключить Telegram-вебхук к новому адресу

Самый простой способ — прямо в браузере телефона откройте (подставив свой токен и свой домен):

```
https://api.telegram.org/bot<ВАШ_ТОКЕН>/setWebhook?url=https://ваш-адрес.up.railway.app/webhook&drop_pending_updates=true
```

В ответ должно прийти:
```json
{"ok":true,"result":true,"description":"Webhook was set"}
```

## Шаг 6. Проверка

- Откройте бота в Telegram, нажмите `/start` — должно ответить мгновенно.
- Пройдите пару кликов по меню, выберите услугу, оформите тестовую заявку — проверьте, что строка появилась в Google Таблице.
- Проверьте статус вебхука в браузере:
  ```
  https://api.telegram.org/bot<ВАШ_ТОКЕН>/getWebhookInfo
  ```
  `url` должен указывать на ваш Railway-домен, `pending_update_count` — 0, `last_error_message` — отсутствовать.

## Что дальше при изменении кода

Просто отредактируйте файл прямо в GitHub (карандаш ✏️ рядом с файлом в репозитории, тоже работает
с телефона) и Commit — Railway подхватит изменения и передеплоит сам, без ручных действий.
Никаких "Manage deployments" и версий, как в Apps Script — этот шаг больше не нужен.

## Что нового в этой версии (калькулятор, финансы, отзывы, привязка номера)

- **Калькулятор класу авто.** Після вибору послуги клієнт обирає клас авто (Седан x1.0 / Кросовер x1.2 / Позашляховик x1.5). Фінальна ціна = базова ціна × коефіцієнт, показується клієнту одразу і саме вона записується в таблицю (у стовпець "Сума").
- **Прив'язка номера телефону до акаунта.** Після першого замовлення номер зберігається в окремій вкладці `Клієнти` (створюється ботом автоматично). При наступному замовленні бот сам пропонує підтвердити збережений номер одним натисканням, замість того щоб знову просити ділитися контактом — можна змінити номер вручну, якщо потрібно.
- **"Кишеньковий бухгалтер".** Якщо адмін пише в чат з ботом `+1500 мийка` або `-450 паста`, бот заносить це у вкладку `Фінанси` (Дата, Тип, Сума, Опис, Хто вніс — створюється автоматично) і одразу відповідає поточним балансом.
- **Авто-запит відгуку.** Коли адмін тисне "🏁 Завершити" (в повній картці заявки або швидкою кнопкою на першому сповіщенні) — клієнту одразу йде запит оцінити роботу від 1 до 5 зірок, оцінка потрапляє в таблицю (стовпець "Оцінка").
- **Виправлення "бот не реагує".** Раніше будь-яка непередбачена помилка під час обробки просто тонула в консолі, і ні клієнт, ні адмін про це не дізнавались. Тепер при будь-якому збої клієнт отримує повідомлення про технічну помилку замість тиші, а адміну одразу приходить сповіщення з текстом помилки — це дозволить миттєво бачити, якщо щось піде не так, замість здогадок по описах "довго думає"/"не реагує".

**Важливо:** через нову вкладку `Клієнти` і розширення таблиці заявок до стовпця H (оцінка) — сервісному акаунту потрібен той самий доступ **Редактор**, який вже був наданий раніше (Крок 2 в цій інструкції). Нових дозволів надавати не потрібно, вкладки бот створює сам при першому зверненні.

## Що нового в попередній версії (Node.js без cold start)

- **Навигация по меню снова через редактирование сообщения** (как было изначально на GAS), а не отдельными новыми сообщениями. Единственное исключение — момент запроса телефона: Telegram не позволяет прикрепить клавиатуру "поделиться контактом" через `editMessageText`, это ограничение API, а не архитектуры бота. Поэтому в этот один момент текущее сообщение правится на "Оформлюємо заявку..." и отдельным сообщением приходит запрос телефона.
- **Виїзний детейлінг теперь с 3 пакетами** — Базовий (1000 грн), Стандартний (1500 грн), Ексклюзивний (2200 грн). Цены и описания — в `texts.js` и `SERVICES` в `index.js`, меняются в одном месте.
- **Русский язык убран.** Остались Українська и English, язык по умолчанию — українська.
- **Клиент видит полное подтверждение заказа** (номер заявки, телефон, услуга, цена, дата) сразу после отправки телефона — это уже было реализовано и продолжает работать в новой версии.
- **Мастер/админ получает уведомление с быстрыми кнопками** прямо на самом уведомлении о заказе — "В роботу" / "Завершити" без захода в полную админ-панель, плюс кнопка на полную карточку с заявкой (скидки, смена статуса, смена услуги).
- **Ввод своей цены админом** теперь тоже правит ту же карточку заказа, а не создаёт новые сообщения — при ошибке ввода (не число) сообщение с подсказкой обновляется на месте.

## Отличия от версии на Apps Script

- Нет cold start — процесс работает постоянно, задержки не будет.
- Нет проблемы с 302-редиректом — Node просто отвечает `200 OK` напрямую, без прослойки Google-редиректов.
- Состояние диалога (`state.js`) хранится в памяти процесса, а не в CacheService — при передеплое
  (после каждого Commit в GitHub) активные незавершённые сценарии ("жду телефон", "жду цену от админа")
  сбрасываются. Для этого бота это не проблема — пользователь просто начнёт заново с `/start`.
- Функция `WAKE_UP` и триггер на неё в Apps Script больше не нужны — их можно спокойно удалить
  вместе со старым GAS-проектом после того, как убедитесь, что новый бот работает стабильно.
